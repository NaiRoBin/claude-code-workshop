# Lab 02 — พื้นฐาน Claude Code + Plan mode

> เวลา ~65 นาที · ทำบนโปรเจกต์ตัวอย่าง (provision ไว้บน VM แล้วที่ `~/cc-basics`)
> เป้าหมาย: สั่งงาน, แก้ไฟล์, รันคำสั่ง, ใช้ `/commands`, เข้าใจ permission, git, และ plan mode

---

## เตรียม: บอก Claude ว่าทำงานบน VM

> ไม่เคยใช้ ssh มาก่อนก็ทำตามได้ — ไม่ต้องเข้าใจ ssh ลึกซึ้ง แค่ทำตามขั้นตอนนี้ทีละก้าว
> ส่วนที่ต้องรู้จริง ๆ (สร้าง key, ตั้ง config) ทำไปแล้วใน lab 01 แล้ว รอบนี้แค่ "ใช้งาน" มัน

**ขั้นที่ 1 — เปิด terminal แล้วรัน `claude`**
```powershell
claude
```
เปิดที่โฟลเดอร์ไหนก็ได้บนเครื่อง Windows — **ไม่ต้อง cd ไปไหน ไม่ต้อง copy sample-project
มาที่เครื่องตัวเอง** เพราะโปรเจกต์ตัวจริงอยู่บน VM แล้ว (ผู้สอน provision ไว้ให้ที่
`~/cc-basics`) เราจะบอกให้ Claude ไปทำงานที่นั่นแทน

**ขั้นที่ 2 — พิมพ์ข้อความนี้บอก Claude ก่อนเริ่มโจทย์ใด ๆ**
```
เราจะทำงานบน remote VM ผ่านคำสั่ง `ssh myvm "..."`
โปรเจกต์ตัวอย่างอยู่ที่ `~/cc-basics` บน VM แล้ว (provision ไว้ให้แล้ว)
ใช้ ssh คำสั่งนี้อ่าน/แก้ไฟล์และรันคำสั่งทุกครั้งตลอด lab นี้
```

**ขั้นที่ 3 — สิ่งที่จะเห็นต่อจากนี้ (เป็นเรื่องปกติ ไม่ต้องแปลกใจ)**
- Claude จะตอบรับ แล้วเริ่มพิมพ์คำสั่งที่หน้าตาเหมือน `ssh myvm "cd ~/cc-basics && ..."`
  ทุกครั้งที่ต้องอ่าน/แก้ไฟล์หรือรันคำสั่ง — นี่คือ Claude "เข้าไปทำงาน" บน VM แทนเรา
  ผ่าน SSH ที่ตั้งไว้แล้วใน lab 01
- ก่อนรันคำสั่งแรก Claude จะโชว์ **permission prompt** ถามว่าจะรันคำสั่งนี้ไหม — กด
  allow ได้เลย (ตั้งใจให้ขอทุกครั้งเพื่อให้เราคุมได้เสมอ ไม่ใช่ error)
- ถ้า Claude "ค้าง" ไม่ตอบนานผิดปกติหลังยิงคำสั่ง ssh ไป → ให้สงสัยว่า ssh ไม่
  non-interactive กลับไปดู Checkpoint เรื่อง SSH ใน lab 01 อีกครั้ง

**ขั้นที่ 4 — ทดสอบว่า pattern นี้ทำงานจริง ก่อนเข้าโจทย์**
```
ลองอ่านไฟล์ README.md ในโปรเจกต์มาสรุปให้ฟังหน่อย
```
ถ้า Claude สรุปเนื้อหาไฟล์ให้ถูกต้อง = พร้อมทำโจทย์ที่ 1 ต่อได้เลย

## 1. คุยกับ Claude Code (prompting) (10 นาที)
ลอง:
```
อธิบายว่าโปรเจกต์นี้ทำอะไร โดยอ่านจากไฟล์ในโฟลเดอร์
```
เคล็ดลับ: บอก **เป้าหมาย + บริบท + ตัวอย่าง** ยิ่งชัด ผลยิ่งดี

## 2. แก้ไฟล์ (15 นาที)
```
เพิ่มฟังก์ชัน multiply(a, b) ใน src/calculator.js พร้อมคอมเมนต์ภาษาไทยสั้น ๆ
```
- ดู **diff** ที่ Claude เสนอ ก่อนกด allow
- ลองสั่งแก้ต่อ: `เปลี่ยนชื่อ multiply เป็น mul และอัปเดตที่เรียกใช้ทั้งหมด`
- ตรวจเองได้ผ่าน ssh เช่นกัน: `ssh myvm "cat ~/cc-basics/src/calculator.js"`

## 3. รันคำสั่ง & permission (10 นาที)
```
รันเทสต์ให้หน่อย
```
สังเกตว่า Claude ขออนุญาตก่อนรันคำสั่ง — เข้าใจว่า **เราคุมได้เสมอ** ว่าจะให้รันอะไร

## 4. Slash commands (10 นาที)
พิมพ์ `/` เพื่อดูคำสั่งที่มี ลองใช้:
- `/help` — ความช่วยเหลือ
- `/clear` — ล้าง context เริ่มใหม่
- `/commands` หรือดูรายการ skill/commands ที่ติดตั้ง

## 5. Git (10 นาที)
```
git init ให้หน่อย แล้ว commit งานปัจจุบันด้วยข้อความที่เหมาะสม
```
ดูว่า Claude รัน git ให้อย่างไร (ขออนุญาตก่อน)

---

## 6. Plan mode — ปูทางช่วงบ่าย (10 นาที)

สำหรับงานใหญ่ ให้ Claude **วางแผนก่อนลงมือ**:
```
ฉันอยากเพิ่มฟีเจอร์อ่านไฟล์ CSV เข้ามาใน calculator นี้
ช่วยวางแผนก่อน (plan mode) อย่าเพิ่งแก้โค้ด
```
- Claude ร่างแผนให้ตรวจ → เราแก้/อนุมัติได้
- อนุมัติแล้วจึงลงมือ

**`CLAUDE.md`**: สร้างไฟล์นี้ในโปรเจกต์เพื่อบันทึกกติกา/บริบทที่อยากให้ Claude จำทุกครั้ง
```
สร้าง CLAUDE.md อธิบายว่าโปรเจกต์นี้ใช้ Node, เขียนคอมเมนต์เป็นภาษาไทย, และใช้ conventional commits
```

### ✅ Checkpoint 2
- แก้ไฟล์ผ่าน Claude ได้, เห็น diff/permission, commit ผ่าน git ได้
- เข้าใจว่า plan mode ใช้เมื่อไร และมี `CLAUDE.md` ในโปรเจกต์
- ตรวจทุกอย่างบน VM ได้เองผ่าน `ssh myvm "cd ~/cc-basics && git log --oneline"`
