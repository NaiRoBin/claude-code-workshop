# Lab 04 — Use case จริง: ใช้ Claude Code สร้างโปรเจกต์ (หัวข้อหลัก)

> เวลา ~75 นาที (สาธิต ~20 + ลงมือ ~55) · ทำบน Windows notebook
> เป้าหมาย: เห็นและทำตาม workflow จริงที่ใช้ Claude Code สร้างงานตั้งแต่ต้นจนจบ —
> **workflow เดียวกับที่ผู้สอนใช้สร้าง workshop นี้ขึ้นมา**

---

## แนวคิด: "เรียน Claude Code ด้วยการดูมันทำงานจริง"

workshop ชุดนี้ (ทุกไฟล์ที่คุณกำลังอ่าน) ถูกสร้างด้วย Claude Code เอง ผ่านขั้นตอน:

```
1) เรียก skill grill-me/grilling  →  Claude ซักถามความต้องการทีละข้อ
2) เข้า plan mode                 →  Claude ร่างแผนเป็นไฟล์ให้ตรวจ
3) ExitPlanMode (อนุมัติแผน)      →  Claude ลงมือสร้างไฟล์ทั้งชุด
4) ทบทวน/แก้ไขเป็นรอบ ๆ           →  ปรับ scope, เพิ่มเนื้อหา
```

รายละเอียดเต็มของ session จริงดูที่ [`../examples/how-we-built-this.md`](../examples/how-we-built-this.md)

## ส่วน A — ผู้สอนสาธิต (~20 นาที)

ผู้สอนเปิด `claude` ในโฟลเดอร์ว่าง แล้วสาธิตสด:

1. **ตั้งโจทย์ + เรียก grilling**
   ```
   /grilling ฉันอยากได้ CLI เล็ก ๆ แปลงไฟล์ CSV เป็น JSON
   ```
   ให้ผู้เรียนเห็นว่า Claude ถามกลับ (ภาษาอะไร, มี header ไหม, ฯลฯ) — เน้นว่า
   "การถูกซักช่วยให้ได้สเปกชัด ก่อนเขียนโค้ด"

2. **เข้า plan mode** ให้ Claude ร่างแผน แล้วชี้ให้ดูว่าแผนคืออะไร ตรวจ/แก้ก่อนอนุมัติ

3. **อนุมัติแผน** แล้วปล่อยให้ Claude สร้างไฟล์ + รัน — ชี้ให้ดู permission prompt, การรันคำสั่ง, การแก้ไฟล์

4. **ทบทวน**: สั่งแก้ 1 อย่าง เช่น "เพิ่ม flag `--pretty`" ให้เห็นการวนแก้

## ส่วน B — ผู้เรียนลงมือ mini-project (~55 นาที)

เลือก 1 โจทย์ (หรือคิดเอง) แล้วทำด้วย workflow เดียวกัน:

- **โจทย์ 1 (non-dev friendly):** ให้ Claude Code สร้างสคริปต์อ่านไฟล์ CSV แล้วสรุปสถิติ + เขียนออกเป็น Markdown report
- **โจทย์ 2:** สร้าง REST API เล็ก ๆ (todo list) + เทสต์ (ลองใช้ `/tdd` ที่ติดตั้งใน Lab 03)
- **โจทย์ 3:** เขียน skill ส่วนตัวที่ช่วยงานประจำของคุณ (เช่น สรุป log, ร่างอีเมล)

### ขั้นตอนแนะนำ
```
1. เปิดโฟลเดอร์โปรเจกต์ใหม่:   mkdir my-mini && cd my-mini && claude
2. /grilling <โจทย์ของคุณ>      # ให้ Claude ซักสเปก
3. ขอให้ Claude เข้า plan mode และร่างแผน — ตรวจแผน
4. อนุมัติ แล้วให้ Claude สร้าง/รัน
5. เพิ่ม CLAUDE.md สั้น ๆ อธิบายโปรเจกต์ให้ Claude จำ context
6. วนแก้จนพอใจ แล้วลอง /commit-msg (skill ที่สร้างใน Lab 03) เพื่อร่าง commit
```

### ทริคที่ควรเน้นกับผู้เรียน
- **ให้ context ดี ๆ**: บอกเป้าหมาย ข้อจำกัด ตัวอย่าง input/output
- **ใช้ plan mode ก่อนงานใหญ่**: ตรวจแผนถูก ประหยัดเวลา/โทเคน
- **`CLAUDE.md`**: บันทึกกติกา/บริบทที่อยากให้ Claude จำทุกครั้ง
- **อ่าน diff ก่อนกด allow**: เข้าใจว่าจะแก้อะไร

### ✅ Checkpoint 4
คุณมีโปรเจกต์เล็ก ๆ ที่ทำงานได้จริง สร้างโดยผ่าน grilling → plan → generate และวนแก้อย่างน้อย 1 รอบ
